# 自动初始布局：实现与验证

2026-09-13。已实现“固定轨迹 → 自动生成方块初态 → 物理抓取探测 → 联合筛选盒子 → 完整回放与扰动验收”的批量入口。

第 0 条已经自动找到能把两个方块抬起的候选位置；完整入盒和复放稳定性仍未通过，**当前成功数据集数量为 0**。程序将其拒收，没有更改参考轨迹或把抓取探测标成完整任务成功。

## 实测结果

- 第 0、20、84 条完成自动源数据核对、阶段识别、方块类型识别和 IK 准备；没有为这些演示填写抓取时刻或方块位置。
- 第 0 条的一个自动候选中，蓝块最大抬升约 **6.9 cm**，红块约 **6.6 cm**。
- 两次释放产生了 **900 个**可共同容纳落点的盒子候选，但都未通过释放前搬运轨迹与盒壁的碰撞筛选。
- 同一抓取布局在录制复验中，蓝块仍被抬起，红块没有稳定抓住。因此缓存策略会将该布局标记为不可可靠复用，不能以一次成功代表稳定区域。
- 工程验收独立核对了每个控制周期的参考关节命令，误差为 **0 rad**；所有尝试使用同一轨迹哈希和同一时间缩放。实际执行误差另行记录。

这些结果表明“按固定动作自动求初始摆放”已可执行，同时也说明“抓取候选有效”和“完整任务稳定成功”必须分别验收。没有跑完全部 85 条，也没有验证真机训练效果。

## 实现入口

[运行说明与完整命令](../../assets/room01/umi_auto/README.md)。主要文件：

- `room01_sim/umi_layout.py`：阶段/资产识别、手部碰撞几何、候选抓取、盒子共同落点与扫掠检查、缓存一致性。
- `room01_sim/umi_auto_runtime.py`：初始位姿写入后的物理回放、记录与任务判定。
- `scripts/run_room01_umi_batch.py`：批量、预算、中断后继续、成功导出与拒收记录。
- `scripts/validate_room01_umi_auto.py`：独立验证固定轨迹和数据标记。

通过了 8 项行为测试：阶段识别不依赖固定时间、颜色识别不把皮肤当红块、有效数据不被未使用的无效原始前缀拒绝、旋转碰撞检查、共同盒子区域、低位扫掠拒收、轨迹变更检测，以及失败复验使成功缓存失效。
